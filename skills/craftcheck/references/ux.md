# Journeys and interaction states

Name the user's success condition and preserve the controls needed to reach it.
Trace complete tasks with actual data and the supported input methods.

For each applicable operation inspect loading, empty, error, success, partial,
unavailable, permission and expired-session states. Check double activation,
refresh, back/forward, interruption, slow responses, stale data, cancellation,
retry and unknown external outcomes. State what users see and what they can do.

Use realistic stress cases: long names, translated labels, no results, large
collections, missing images, zero/negative values and partially completed work.
Check save state and recovery. A successful toast does not establish a saved
record; verify the actual result when authorized and possible.

Keep important actions discoverable on touch and keyboard. A dense professional
workspace can be appropriate. Progressive disclosure should retain essential
costs, consequences and recovery information. Do not remove useful complexity
merely to simplify a screenshot.

For products with accounts and billing, trace relevant recovery, linking, plan
changes, cancellation, export and deletion paths. Do not invent policies or
controls that the product does not have.

Use P and UX catalogue entries. The CLI can flag likely placeholders and ambiguous
static form behaviour; it does not execute complete browser journeys.
