# Audit an existing artifact

1. Define scope and capabilities. A supplied image supports visual observations;
   source supports static tracing; runtime claims require actual execution evidence.
2. Capture the baseline and required behaviours. Use `audit TARGET --out REPORT_DIR`
   for supported static checks when appropriate. The helper ignores secret files,
   dependencies, generated output and symlinks and records relevant input limits.
3. Inspect the relevant artifact directly. For an interface, walk complete key tasks
   and applicable loading, empty, failure, permission and partial states. For writing
   and media, check actual claims, sources, timing and output quality.
4. For operational UIs, compare the first screen's action/metric density against
   copy, repeated badges, duplicate navigation labels, unexplained icons and
   dividers. Record where they obscure data or require scanning. Do not call
   a visual pattern defective merely because it appears in a catalogue.
6. Challenge each suspected issue. Consider existing controls, the audience, accepted
   choices, legitimate examples and what evidence is unavailable.
6. Separate confirmed observations, supported concerns, tentative review prompts,
   accepted preferences and unassessed domains. Absence of findings is valid.
7. Rate assessed domains using references/ratings.md. Bind imported review JSON to
   the current inputDigest; list evidence and reviewer identity.

Each finding needs a concrete consequence and recommendation. Avoid quotas, blanket
font bans, claims of AI authorship, or security findings based only on missing hardening.
Use the report schema and review schema for structured output. Raw customer data and
credentials do not belong in excerpts. Keep report-only work separate from repairs.
