# Improve, check, and repeat

The user must have authorized changes to the selected artifact. Honor existing
authorization for routine reversible repairs; new scope, publication or paid work
does not follow automatically.

1. Establish a baseline, actual requirements and what must survive. Use the
   [product checklist](../references/release-review.md) and
   [repair instructions](../references/repairs.md). Keep useful states,
   price/credit information, navigation, accessibility, terminology, API
   behaviour and accepted identity.
2. Find the root cause and choose a focused repair. Prefer existing services and
   components over a second path or manually patched materialized output.
3. For operational interfaces, list each repeated headline, secondary line, badge,
   icon and separator, and ask whether it conveys a decision, status, relationship
   or recovery path. Remove redundant ornament *only where task evidence supports it*.
   Keep a single truthful data-provenance marker when demo/live data differs.
4. Change the authoritative source. Use a reversible diff or the helper's narrow
   source edits. Do not rewrite the entire artifact to remove a stylistic signal.
5. Run the relevant checks immediately. A command's successful exit is evidence of
   its exit, not independent proof of all behaviour it prints.
6. Inspect the changed artifact and original failure. Verify legitimate behaviour,
   adjacent states and the preservation contract as appropriate.
7. Rerate assessed domains against the same rubric and evidence bar. Create a new
   review tied to current inputDigest. Keep earlier ratings and failed attempts.
8. Continue while useful progress is demonstrated and work remains authorized.

For the executable controller, use `loop TARGET --apply --out REPORT_DIR`.
Built-in repairs handle configured document language, restrictive viewport zoom,
ordinary HTML and native JSX new-tab isolation, adjacent identical CSS declarations,
and absent framework header suppression in supported literal Next.js configs.
Use `plan TARGET --json --no-save` for the available edits and verification.

For an integrated semantic loop, configure reviewer, fixer and checks as command
arrays and use `--allow-exec`. The reviewer receives SLOPPYAI_REQUEST and writes
fresh review JSON to SLOPPYAI_REVIEW. The fixer receives the current report and
preservation contract. Both receive the checklist, repair guide and rule-specific
verification steps. The controller pins the initial configuration and reruns it.
An authorized external agent may send selected artifact evidence to its provider.

Stop when scoped targets are met, a regression occurs, progress stalls, bounds are
exhausted, the user cancels, or a required new decision is unavailable. Preserve the
latest evidence and mark outstanding concerns. Never increase a rating or delete a
feature to evade a check. Do not silently drop a failed attempt after a passing retry.

Use `watch TARGET` for bounded checks on changed inputs. It creates no daemon or
scheduled automation. Review the stop reason and coverage before describing success.
