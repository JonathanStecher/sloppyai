# Improve, check, and repeat

The user must have authorized changes to the selected artifact. Honor existing
authorization for routine reversible repairs; new scope, publication or paid work
does not follow automatically.

1. Establish a baseline, actual requirements and what must survive. Read only the
   applicable references. Keep useful states, price/credit information, navigation,
   accessibility, terminology, API behaviour and accepted identity.
2. Find the root cause and choose a focused repair. Prefer existing services and
   components over a second path or manually patched materialized output.
3. Change the authoritative source. Use a reversible diff or the helper's narrow
   source edits. Do not rewrite the entire artifact to remove a stylistic signal.
4. Run the relevant checks immediately. A command's successful exit is evidence of
   its exit, not independent proof of all behaviour it prints.
5. Inspect the changed artifact and original failure. Verify legitimate behaviour,
   adjacent states and the preservation contract as appropriate.
6. Rerate assessed domains against the same rubric and evidence bar. Create a new
   review tied to current inputDigest. Keep earlier ratings and failed attempts.
7. Continue while useful progress is demonstrated and work remains authorized.

For the executable controller, use `loop TARGET --apply --out REPORT_DIR`. It fixes
only missing document language when an actual language is configured, restrictive
viewport zoom, and ordinary new-tab opener relationships. Explicit `rel=opener`
needs contextual review. Other findings need the coding agent or an authorized fixer.

For an integrated semantic loop, configure reviewer, fixer and checks as command
arrays and use `--allow-exec`. The reviewer receives SLOPPYAI_REQUEST and writes
fresh review JSON to SLOPPYAI_REVIEW. The fixer receives the current report and
preservation contract. The controller pins the initial configuration and reruns it.
The hooks may use the user's chosen agent; sloppyai itself makes no AI API calls.

Stop when scoped targets are met, a regression occurs, progress stalls, bounds are
exhausted, the user cancels, or a required new decision is unavailable. Preserve the
latest evidence and mark outstanding concerns. Never increase a rating or delete a
feature to evade a check. Do not silently drop a failed attempt after a passing retry.

Use `watch TARGET` for bounded checks on changed inputs. It creates no daemon or
scheduled automation. Review the stop reason and coverage before describing success.
